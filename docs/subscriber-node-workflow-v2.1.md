# v2.1：以代理节点分配订阅用户

普通创建流程为：填写用户及配额 → 选择代理节点或节点组 → 只读预览 → 管理员确认 → 保存任务并配置认证 → 全部目标确认后启用 → 创建客户端订阅链接。

Subscriber 表达身份、额度与节点权限；Node 表达订阅连接资源；Endpoint 表达 Address/Port/Host/SNI；Inbound 为核心协议入口；Client 为该用户的认证身份。普通用户表单不再要求选择 Inbound。原生 Client 纳管保留为明确的管理员高级流程，不重复添加原生账号，也不自动接管为 Desired。

## 节点授权

新增 `004_subscriber_node_workflow.sql`，不修改已执行 001–003。新流程创建的用户开启 `node_authorization_required`；每个节点授权同时保存稳定 Inbound ID，渲染器前的解析层逐项验证。订阅定义、格式选择或动态分组不能绕过节点授权。

创建时的节点组按当时成员展开并去重，授权保存为节点快照。组新增成员不会自动授权或创建 Client。已有用户通过“分配节点”追加授权，已有认证可复用；本版不通过取消勾选隐式撤销既有权限，也不删除核心用户。对旧用户追加节点不改变既有权限模型，旧订阅 Token 和动态分组保持原语义。若要将旧用户收紧为新模型，需要另行明确迁移授权，不能静默缩小已有订阅。

同一入站的多个节点只有一个认证目标、一个凭据绑定，沿用既有按实例/身份去重的计费逻辑，不按节点倍增流量。不同入站分别配置不同 Client。代理链的计费来源仍须在高级凭据管理明确选择，不把出口和入口重复计费。

## 任务与安全

预览仅读已保存数据库，不探测核心、不生成凭据、不创建用户。预览摘要包含节点定义、分组展开结果、核心 endpoint/tag/protocol 与能力状态。提交在同一个事务重新核对摘要，创建用户、精确节点授权及所有目标任务；提交前失败全部回滚。只在提交成功后运行核心操作。

父任务的子请求 ID 固定，由请求 ID 和稳定入站 ID 生成。复用已有经过验证的 Xray 读后写/回读及加密 Desired；Hysteria2 仅使用明确配置并确认的 HTTP 认证后端，不伪造 AddUser。sing-box 等无已实现动态配置能力的节点在预览中明确阻止；可先纳管原生用户，再复用其绑定。

每次请求最多执行 18 秒，各目标最多 4 秒；未完成任务落库，按最久未尝试顺序重试，避免失败实例阻塞后续目标。任务详情显示每目标状态与原因，不输出 Desired、UUID、密码或 API Secret。重试核对精确目标及实例/来源状态，目标变化不自动写入新目标。全部任务就绪前，新用户默认停用；管理员编辑/停用后，配额修订保护阻止后续重试恢复原启用意图。完成任务不会自动旋转 Token 或创建订阅链接。

`POST catalog/subscriber-node-requests/preview`、`POST catalog/subscriber-node-requests`、`POST catalog/subscriber-node-requests/{request}/retry` 与 GET 任务/授权/详情接口均位于管理员鉴权及写请求 CSRF 保护内。

## 升级与验证

这是已有 v2 数据库的追加迁移，不是再次清库。升级前停止 TML，备份一致的 SQLite 数据库、原镜像和 `TML_MANAGED_KEY_FILE`，用新镜像启动后自动执行 004；远程核心配置不变，不需要重启核心。本版只改变 TML 的界面、授权与配置编排。回滚应恢复配套数据库与镜像，不能将旧镜像直接写入已迁移数据库。

验证包含同入站多入口去重、组成员变化、未授权节点过滤、已有认证复用、部分失败与幂等重试、管理员停用保护、过期预览及目标变更拒绝、管理员鉴权、旧 v2 数据保留及响应式浏览器流程。隔离测试的客户端和流量不代表生产数据。
