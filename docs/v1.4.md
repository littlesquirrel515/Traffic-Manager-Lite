# Traffic Manager Lite v1.4 交付与部署说明

## 1. Hysteria2 方向审计

原实现 `Upload=rx / Download=tx` 已确认反转。它误把计数器理解成服务器与代理客户端之间的收发。

Hysteria2 2.13.0 官方 `core/server/config.go` 明确规定 TrafficLogger 的 Tx/Rx 指服务器与远端代理目标之间的方向；`copy.go` 的实际复制调用和真实流量测试一致：

| Traffic Stats API | 实际含义 | TML 客户端视角 |
|---|---|---|
| tx | 代理服务器发往目标 | Upload |
| rx | 代理服务器从目标收到 | Download |

已修正现代 coremonitor 与旧 adapter 两条采集路径。新计数器使用 `hy-client-direction-v2` epoch，在升级时重新建立基线，避免把旧方向计数器与新计数器相减。数据库增量、小时、日、月查询及后台均沿用统一客户端方向。诊断只读，无 clear/kick。

官方依据：[Traffic Stats API](https://v2.hysteria.network/docs/advanced/Traffic-Stats-API/)、[TrafficLogger 定义](https://github.com/apernet/hysteria/blob/app/v2.13.0/core/server/config.go)、[copyTwoWayEx 调用](https://github.com/apernet/hysteria/blob/app/v2.13.0/core/server/copy.go)。不要仅凭 TX/RX 名称推断方向。

## 2. sing-box 1.14.3 官方核查

2026-10-10 核对正式版 1.14.3、原生 API version 4。隔离 protobuf 为官方 wire 字段的只读投影，未引入 Xray/V2Fly 服务名。

| Provider | 已核实能力 | 限制及使用规则 |
|---|---|---|
| Config | VLESS、Trojan、Hysteria2、AnyTLS 配置资产，所有 inbound 与用户计数 | 文件可读不等于运行时已加载；同名用户按 inbound 分开；合并配置/动态来源不能仅凭单文件声称完整运行时用户 |
| Native gRPC | GetVersion、GetStartedAt、SubscribeServiceStatus、SubscribeStatus、SubscribeConnections | 没有完整服务端用户枚举或服务端用户 CRUD；公开 API 中的其他客户端/配置控制方法不能冒充服务端用户管理 |
| Clash | 版本、连接、实例累计上传下载、目标与连接元数据 | 不作为完整 Clients 来源，不猜测用户归属；仅保留实例级流量 |
| V2Ray Stats | 独立实验性服务 `experimental.v2rayapi.StatsService`，实际配对计数器探测 | 本次官方发布构建没有启用 with_v2ray_api；用户计数需实际支持、启用并唯一匹配配置用户，不能只看端口 |

Native 连接具有 ID、inbound、user、uplinkTotal/downlinkTotal。只对配置中唯一匹配的 `(instance,inbound,user)` 归属计量。首次看到连接建立基线，之后累计实际观测到的差值，重启使用实际 GetStartedAt 隔离连接 ID。初始 reset 快照含活动连接和有界关闭连接历史，关闭连接不能判在线。

**这些差值是已观测用户流量，不是完整历史用户累计流量。** 两次轮询之间出现并消失、或已退出核心连接缓存的连接可能无法完整计量。不能分摊实例总量补齐。UI 明确标注覆盖限制；实例总量独立保留，优先 Native，Clash 降级，不相加。在线指标表示会话/连接观测，不声称物理设备数或完整在线 IP；数据缺失和过期显示 Unknown。

实际方法决定能力；未配置显示 Disabled，调用失败单独保留对应 Provider 状态。版本变化、Provider 切换、计数器回退重新建立基线，无法获取启动证据的不可观测重启仍不能补算。

官方依据：[1.14.3 StartedService schema](https://github.com/SagerNet/sing-box/blob/v1.14.3/daemon/started_service.proto)、[StartedService 实现](https://github.com/SagerNet/sing-box/blob/v1.14.3/daemon/started_service.go)、[原生 API 配置](https://sing-box.sagernet.org/configuration/service/api/)、[V2Ray API](https://sing-box.sagernet.org/configuration/experimental/v2ray-api/)、[Clash API](https://sing-box.sagernet.org/configuration/experimental/clash-api/)。

## 5. 用户管理实现及启用

默认仍为只读采集。官方原生 API 没有服务端用户 CRUD，管理通过 **独立宿主代理** 完成；不挂载 Docker Socket 到 TML。

代理只接收预设实例的用户操作和 hash，不接收任意命令、路径或容器名。固定执行 Docker inspect、容器内 `/usr/bin/sing-box version/check`、指定容器 restart。配置写入仅适配已验证 1.14.3；其他版本只读检测仍可使用，写操作拒绝并要求先验证升级。

流程：读取指定有效文件 → hash 防并发覆盖 → 私有备份 → 只改目标 inbound.users → JSON/官方 check → 保留权限/所有者原子替换 → PendingRestart → 后台管理员再次确认连接中断 → 固定容器重启 → 实际版本、STARTED 状态、GetStartedAt 新 epoch 与 API 健康检查。失败恢复备份并受控恢复；明确展示恢复失败，不谎称成功。支持显式回滚；重复 apply/rollback 不重复重启。删除和重启分别确认。审计只存操作、用户名称、hash、结果，不存 UUID/密码。

### 宿主部署步骤

1. 确认 `sing-box run -c /etc/sing-box/config.json` 使用唯一配置文件。挂载**配置目录**，例如 `/data/sing-box/configs:/etc/sing-box:ro`，不要单文件 bind-mount；单文件挂载旧 inode 会使原子替换不生效，代理会拒绝。合并配置、隐式路径、多个 `-c` 暂不管理。
2. 在宿主构建 `go build -o /usr/local/bin/tml-core-agent ./cmd/tml-core-agent`。容器内二进制须为 `/usr/bin/sing-box`。
3. 将 `deploy/core-agent-targets.example.json` 复制到私有目录，填写真实 TML 实例 ID、Docker 容器名、宿主/容器绝对配置路径、宿主可达原生地址和 Secret。ID 不是服务器 ID。
4. 建立独立 state 目录权限 0700；targets、token 文件权限 0600，token 用 `openssl rand -hex 32` 生成。state 保存原配置备份，包含原始凭据，只供授权宿主管理员访问。Linux 同一 state 有单进程锁；Windows 异常退出需核实进程后处理残留锁。
5. 启动下述固定宿主代理。默认 loopback；若 TML 在 Docker，替换为该 Docker 网络的宿主私网 IP，仅允许 TML 访问该私网端口。不要绑定公网/0.0.0.0，不添加公网端口映射。代理执行 Docker CLI 的宿主账户本身具有 Docker 管理权限，应限定其用途；代理不是 Docker 权限隔离容器。

```sh
tml-core-agent -listen 127.0.0.1:8091 \
  -targets /data/traffic-manager-lite/core-agent/targets.json \
  -token-file /data/traffic-manager-lite/core-agent/token \
  -state-dir /data/traffic-manager-lite/core-agent/state
```

6. 外层 `/data/traffic-manager-lite/.env` 设置 `TML_CORE_AGENT_URL=http://实际宿主私网IP:8091`、`TML_CORE_AGENT_TOKEN=token文件内容`，仅重建/重启 TML 后生效。未设置时用户写操作 Disabled。TML 到代理限定私网/loopback、无代理转发/重定向、DNS 实际拨号校验。
7. TML “只读配置完整路径”填写 **TML 容器内**可读配置路径，单独只读挂载同一宿主配置目录。它不是代理 targets 中的宿主路径。统计 API、原生 API、Clash 地址按各自体系填；sing-box 内置 Hysteria2 inbound 不使用独立 Hysteria2 Traffic Stats API。

API 原生监听/Secret 必须实际启用；若代理通过宿主 loopback 获取 API，可只发布 `127.0.0.1:19090:19090`，TML 的采集优先 Docker 内网。后台展示配置资产；运行时有效性没有受控启动/配置证据时为 Unknown，不能凭文件 hash 声称已生效。

## 9. 历史流量修复

旧代码已确认方向错误，但无法仅凭旧数据库行判断它是否经历导入或其他修正。因此 schema 迁移不自动交换；后台显示方向待核实、候选记录数。

默认只读审计：

```sh
tml-traffic-audit --db /data/traffic-manager-lite/data/traffic.db \
  --timezone Asia/Shanghai --instance 实际HY实例ID \
  --before 2026-10-10T00:00:00+08:00
```

`--before` 是排他截止时间，必须在该实例切换新方向之前。时区必须与数据库固定统计时区一致。先核实选定范围全由旧 TML adapter 写入；无法证明、已纠正或混合归档保持未核实。

确认来源后停止 **TML 监控服务**（不是代理核心），使用新 audit 二进制离线执行：

```sh
tml-traffic-audit --db /data/traffic-manager-lite/data/traffic.db \
  --timezone Asia/Shanghai --instance 实际HY实例ID \
  --before 经核实的截止时间 --repair --confirm-legacy-tml \
  --evidence '旧部署版本/哈希及选定范围唯一来源的依据，不含密钥' \
  --backup-dir /data/traffic-manager-lite/backups
```

修复前自动一致性备份（0600），同事务交换选定旧明细和归档贡献、按贡献差异修正小时/日权威汇总、保留月查询一致性、修正对应旧 cursor 与来源证据，最后再次核对双 ledger。截止时间切分归档或包含已纠正证据时拒绝。记录备份路径、截止、数量、来源证据；同实例/修复 profile 只执行一次，再调用不二次交换。

**本次未读取或修复你的生产数据库。** 已执行的是隔离测试数据库的完整修复测试。

## 10. 限制与未验证

- 你的 VPS、现有 Docker 实例/API Secret/真实配置/Nginx、历史数据库及生产升级：未验证、未改动。需按上面路径与私网映射部署后执行现场验收。
- Native 不提供服务端完整用户枚举/CRUD；配置管理需要受控宿主代理，未启用不会擅自重启。
- 原生连接观察的用户流量有采样覆盖限制，不是账单级完整计数；物理设备和完整 IP 数 Unsupported/Unknown。
- 官方发布构建 V2Ray Stats 未启用。自定义 with_v2ray_api 构建的真实多协议用户计数：未验证；仅有独立服务与归属测试，不宣传生产支持。
- 多文件合并、远程/动态用户来源不能凭单文件判定完整；配置写操作保守拒绝。写操作只适配 1.14.3，升级版本应先校验官方 schema 与 check/重启行为。
- 长期资源/大规模并发、生产网络中断覆盖损失、所有其他协议组合：未验证。
- 迁移前历史缺少逐记录来源不能补造；方向未知保持待核实，不自动交换其他核心或整个数据库。
