# v2.2.1：明确节点授权与连接入口备注

## SG-5 自动勾选的原因

线上 SG-5 的稳定 Node ID 是新资源，没有任何用户的显式 `subscriber_node_grants`，但它被加入 SG-G1。两个旧用户仍为 `node_authorization_required=0`，旧订阅关联这个分组，回显和发布阶段因而动态展开当前成员。问题来自旧授权兼容规则，不是创建 Host 时添加了核心 Client。

006 追加迁移将旧用户转换为精确节点授权：保留既有显式授权与明确保存的节点选择；旧分组按已保存的统一链接创建时点固化，没有统一链接时按各旧订阅的创建时点固化。分组内晚于该证据时点出现、又没有明确选择记录的节点不自动授权。迁移记录 `explicit_node_authorization` 审计，不重置 Token、配额或流量，不改写客户端凭据。

SG-5 创建于两个统一链接的已保存时点之后，且没有显式授权，因而不进入任何用户的授权清单。旧节点、显式晚选节点和已撤销节点分别按原记录保留/过滤。之后新增 Host、同入站的其他入口或调整节点组，都不会自动分配给其他用户。旧订阅 URL 继续可用，但发布阶段也要经过精确授权过滤。

普通新建订阅用户和原生用户纳管均开启精确节点授权。纳管 Client 只建立真实身份归属，不代表可用该入站的所有节点；之后仍须明确分配代理节点。

## 模块职责

订阅用户负责身份、配额、节点权限；Node/Host 负责客户端连接定义和稳定 Inbound 映射。用户分配节点后，应用配置服务按映射调用核心适配器配置/复用认证，再将结果关联用户；用户界面不需要手工管理底层凭据。订阅用户页移除“高级凭据管理”按钮及其表单操作。

创建 Host 时尚没有具体用户认证意图，只创建连接资源、绑定及 Proxy Node，不创建 Inbound 或 Client。不能把配置用户的副作用放进 Host 新增，否则每新增一个入口都可能产生无归属账号或重复计费。

## 备注

连接入口列表与入站详情的连接列表都直接显示“备注”列，读取同一 Endpoint 的 `description`。保留换行、长文本自动换行，以普通文字转义展示 HTML；不依赖鼠标悬停。共享入口的备注仍通过共享定义编辑，避免同一信息多处互相覆盖。
